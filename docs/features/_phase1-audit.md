## Core document/storage model (reuse — do not duplicate)

- `Document` → `DocumentFile` (`apps/documents/models.py`). `DocumentFile` is **encrypted
  at rest** (AES-256-GCM, wrapped DEK, nonce, gcm_tag), with `checksum`, `content_type`,
  `file_size`, `file_uuid`, trash flags, `is_previewable()`.
- `DocumentVersion` links a document to a file with a `version_type` + metadata snapshots.
- Encryption service `apps/documents/file_encryption.py`:
  - `encrypt_bytes_into_record(instance, plaintext, filename)` — store generated bytes as
    an encrypted `DocumentFile`.
  - `read_plaintext(instance)` — decrypt an existing file.
  - `sha256_hex(data)` — content hash (exactly what Phase 8 audit needs).

## Tooling available for the gap

- `pypdf==6.13.2` (read/stamp/merge PDF pages), `fpdf2==2.8.7` (generate overlay PDF),
  `Pillow==12.2.0`, `pdf2image`. **Server-side Fill & Sign overlay + flatten is feasible
  with existing deps — no new heavy library needed.**

## Genuine gaps / real work (ranked)

1. **Fill & Sign + Signature Audit Trail MVP (Phases 7–8)** — the one true net-new slice.
   - New models: `PreparedDocument` (original `DocumentFile` → prepared `DocumentFile`,
     `preparation_type`, annotations JSON) and `DocumentSignatureRecord` (signer, method,
     `original_file_hash`, `prepared_file_hash`, audit payload).
   - Service: read original plaintext → render overlay (text/date/check/initials/signature
     image) with fpdf2/Pillow → merge onto PDF pages with pypdf → store as **new encrypted
     DocumentFile** (original preserved) → record hashes.
   - API under `apps/documents` (reuse permissions/ownership). Frontend Fill & Sign tool +
     signed-copy badge + audit section.
   - Honest copy: "Prepare a signed copy. Your original is preserved. Legal acceptance may
     depend on recipient and jurisdiction. This is not a legal certification."
2. **Verify the existing AI flows are real** (run targeted tests; confirm the
   not-configured state) — the user bought Claude credit to test live; without
   `ANTHROPIC_API_KEY` set here, AI_CONFIGURED is false, so I validate the not-configured
   path + mocked tests, and document how to enable.
3. **Cross-feature integration checks** (Phase 12) for the new Fill & Sign output →
   Vault/Pack/SafeSend, reusing existing relations.

## Risks

- `DocumentFile` encryption is non-trivial; the prepared copy MUST go through
  `encrypt_bytes_into_record` (no plaintext-on-disk shortcut).
- PDF overlay must preserve the original and handle non-PDF / image-only inputs honestly
  (no fake fill for unsupported types).
- Keep new endpoints ownership-scoped; no public exposure of prepared copies by default.

## Files likely to change

- `backend/apps/documents/models.py` (+ migration), new `apps/documents/fill_sign.py`
  service, `serializers.py`, `views.py`, `urls.py`, tests.
- `frontend/src/app/(dashboard)/dashboard/documents/.../fill-sign` + a Fill & Sign component;
  signed-copy badge + audit UI on document detail.
